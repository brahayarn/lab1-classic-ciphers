# 2. Теоретичні відомості

**Підстановка** змінює символи, але не їхні позиції. Ключем простої підстановки є
перестановка B алфавіту A: літера `A[i]` замінюється на `B[i]`. Перетворення
оборотне тоді й лише тоді, коли B містить кожну з 33 літер рівно один раз (бієкція
A → B). Розшифрування використовує обернене відображення `B[i] → A[i]`. Оскільки кожна
літера завжди замінюється тією самою, частоти літер, довжини слів і шаблони повторів
зберігаються, тож довгий шифротекст піддається частотному аналізу.

Таблицю B будують із ключового слова W: нормалізують регістр, вилучають повторні літери
(залишаючи першу появу) і дописують решту літер A в алфавітному порядку.

**Шифр Віженера** є періодичною багатоалфавітною підстановкою. Літери та ключ
перетворюють на індекси 0..32, i рахує лише літери алфавіту:

    C_i = (P_i + K_(i mod l)) mod 33,     P_i = (C_i − K_(i mod l)) mod 33.

Одна літера відкритого тексту може переходити в різні літери шифротексту, що вирівнює
розподіл частот. Проте ключ повторюється з періодом l. Підпослідовності з кроком l
зашифровані простим зсувом, тому довжину ключа можна знайти методом Касіскі або за
індексом збігів, а потім розв'язати l простих зсувів.

**Перестановка** не змінює набір символів, лише їхні позиції. У **блоковій** перестановці
для кожного повного блока x довжини n формується `y_j = x_(π_j)`. Обернена перестановка
задовольняє `π⁻¹[π_j] = j`; для π = (3, 2, 5, 1, 4) маємо π⁻¹ = (4, 2, 1, 5, 3).
У **вертикальній** перестановці текст записують по рядках у прямокутник із k стовпцями і
читають стовпці в порядку ключа. Частоти літер при перестановці не змінюються взагалі.

# 3. Специфікація обробки тексту

| Аспект | Прийняте правило |
|---|---|
| Алфавіт | `АБВГҐДЕЄЖЗИІЇЙКЛМНОПРСТУФХЦЧШЩЬЮЯ`, m = 33, індекси 0..32 |
| Кодування | вхідні й вихідні файли UTF-8; BOM на вході ігнорується; `\n` і `\r\n` не змінюються |
| Нормалізація | NFC → `upper()` → NFC (друга NFC — бо `upper()` може дати розкладену форму) |
| Регістр | базовий режим: усі літери у верхньому регістрі; збереження регістру не реалізоване |
| Допустимі символи | 33 літери, пробіли, табуляція, переноси рядків, цифри (Nd), розділові знаки (P*), апострофи `' ʼ ’`, `№`, математичні (Sm) та валютні (Sc) знаки |
| Недопустимі символи | латиниця, інші кириличні літери (Ы, Ё, Ъ, Э), емодзі, керувальні й окремі комбіновані знаки. Результат — повідомлення з кодом символу та позицією, без аварійного завершення |
| Підстановки | символи поза алфавітом зберігаються на своїх місцях і **не** просувають позицію ключа Віженера |
| Перестановки: `preserve` (типовий) | переставляється весь підготовлений текст, включно з пробілами та переносами; повністю зворотний |
| Перестановки: `letters` | спершу вилучаються всі символи, крім літер; незворотний щодо форматування, еталон — підготовлений рядок без пробілів |
| Неповний блок (блокова) | останній блок довжини < n залишається без змін |
| Неповний рядок (вертикальна) | доповнюється службовою літерою (типово `Х`), кількість p (0 ≤ p < k) повідомляється користувачу й передається при розшифруванні; вилучаються рівно p останніх символів |

Еталон зворотності: `D_k(E_k(x)) = prepare(x)`, де `prepare` — нормалізація і зміна регістру.

# 4. Перевірка ключів

Ключ перевіряється до читання й обробки тексту. Повідомлення пояснює, що саме не так.

| Алгоритм | Умова прийняття | Приклад відмови |
|---|---|---|
| Проста підстановка | ключове слово не порожнє, лише літери A; таблиця має довжину 33, лише літери A, без повторів | `таблиця не є перестановкою: повторюються А, відсутні Я.` |
| Віженер | після нормалізації не порожній і містить лише літери A | `ключ Віженера містить символ 'K' поза алфавітом …` |
| Блокова / вертикальна | числа, розділені пробілами чи комами; кожне від 1 до n рівно один раз | `ключ не є перестановкою: повторюються [2], відсутні [3].` / `число 4 поза діапазоном 1..3` |
| Доповнення | ціле, 0 ≤ p < k; довжина шифротексту кратна k | `кількість доданих символів 4 має бути в межах 0..3` |

# 5. Структура програми та ключові рішення

```
classic_ciphers/
  text.py          алфавіт, нормалізація, перевірка символів, режими перестановок
  substitution.py  build_table, validate_table, encrypt, decrypt
  vigenere.py      parse_key, encrypt, decrypt
  permutation.py   parse_permutation, validate_permutation, invert
  block.py         encrypt, decrypt (неповний блок без змін)
  columnar.py      encrypt -> (text, padding), decrypt(text, key, padding)
  analysis.py      частоти, індекс збігів, оцінка довжини ключа (додатково)
  fileio.py        read_text, write_text_atomic
  errors.py        CipherError та підкласи
  cli.py           команди encrypt, decrypt, rules, analyze
tests/             88 тестів unittest
experiments/       run_experiment.py та results/
```

Ключові рішення:

1. **Криптографія відокремлена від інтерфейсу.** Модулі алгоритмів не читають і не друкують
   нічого, лише приймають рядки й повертають рядки або кидають `CipherError`. Тому всі
   алгоритми тестуються без ручного введення, а `cli.py` лише розбирає аргументи і
   перетворює помилки на повідомлення `Помилка: …` та код завершення 1.
2. **Одна функція підготовки тексту** (`text.prepare`) для всіх алгоритмів, тож правила
   нормалізації неможливо застосувати по-різному в різних шифрах.
3. **Розшифрування перестановок повторно використовує зашифрування.** Для блокової
   перестановки обернена перестановка обчислюється один раз (`invert`), а потім
   виконується той самий прохід `_apply`, як радить псевдокод методички:

    ```python
    def _apply(text, perm):
        n = len(perm)
        blocks = []
        for start in range(0, len(text), n):
            block = text[start:start + n]
            if len(block) < n:
                blocks.append(block)            # політика неповного блока
            else:
                blocks.append("".join(block[source - 1] for source in perm))
        return "".join(blocks)
    ```

4. **Вертикальна перестановка повертає кількість доповнення окремо** (`Encrypted(text,
   padding)`), а не вгадує її за кінцем рядка. Тому текст, який сам закінчується на `Х`,
   відновлюється правильно (окремий тест `test_only_known_number_of_pad_chars_removed`).
   Стовпець c прямокутника береться зрізом `grid[c-1::k]`.
5. **Віженер** просуває лічильник ключа лише на літерах алфавіту. Від'ємна різниця при
   розшифруванні приводиться до 0..32 операцією `%`, яка в Python для додатного модуля
   завжди повертає невід'ємний результат.
6. **Атомарний запис файлів.** Результат пишеться у тимчасовий файл у тому ж каталозі,
   а потім `os.replace` підміняє ціль. Якщо ключ чи текст некоректні, вихідний файл не
   створюється. Якщо запис не вдався, наявний файл не пошкоджується.
7. **Файли читаються з `newline=""`**, щоб переноси `\r\n` не перетворювалися і
   режим `preserve` був точно зворотним для файлів.

# 9. Додаткові завдання: частотний аналіз

Команда `python3 -m classic_ciphers analyze` будує гістограму частот, обчислює індекс
збігів (IC) і оцінює довжину ключа Віженера.

| Ранг | Відкритий текст | Шифротекст простої підстановки |
|---|---|---|
| 1 | А — 45 | К — 45 |
| 2 | О — 38 | З — 38 |
| 3 | И — 37 | М — 37 |
| 4 | Т — 37 | Я — 37 |
| 5 | І — 31 | Б — 31 |
| 6 | Н — 30 | Ж — 30 |
| 7 | В — 29 | И — 29 |
| 8 | Е — 20 | Г — 20 |
| 9 | Р — 19 | Й — 19 |
| 10 | С — 19 | Л — 19 |

Розподіл частот простої підстановки є точною перестановкою розподілу відкритого тексту.
IC однаковий: 0,0495 і 0,0495. Тому найчастіша літера шифротексту К майже напевно
відповідає А, і далі ключ відновлюється за частотами. У Віженера IC = 0,0332, що близько
до випадкового тексту (1/33 = 0,0303), тобто розподіл вирівнюється. Проте середній IC
стовпців із кроком L різко зростає саме при L = 6 (0,0485) та L = 12 (0,0481), тож метод
індексу збігів правильно визначив довжину ключа ЗАХИСТ = 6. Тест `test_estimates_key_length_on_sample`
перевіряє це також для ключів довжини 4 і 5.

# 11. Висновки

1. Реалізовано чотири обов'язкові алгоритми з окремими функціями зашифрування,
   розшифрування й перевірки ключів. Усі контрольні вектори збігаються з очікуваними, а
   зворотність підтверджено на 12 фіксованих повідомленнях, 1200 генеративних прикладах і
   власному тексті з 482 літер.
2. Головні джерела помилок реалізації, які довелося явно специфікувати й покрити тестами:
   - порядок алфавіту, зокрема місця Ґ, Є, І, Ї;
   - просування ключа Віженера на пробілах;
   - від'ємна різниця при розшифруванні;
   - змішування 0- та 1-індексації у перестановках;
   - політика неповного блока;
   - видалення «всіх Х наприкінці» замість відомої кількості доповнення;
   - розкладені Unicode-послідовності (Й як И + U+0306);
   - зміна переносів рядків під час читання файлу.
3. Властивість `D(E(x)) = x` гарантує лише коректність, а не безпеку. Проста підстановка
   зберігає частоти літер (IC шифротексту дорівнює IC тексту). Віженер приховує частоти
   лише частково: період ключа виявляється індексом збігів навіть на тексті з менш ніж
   500 літер. Перестановки зберігають склад літер повністю. Жоден із шифрів не забезпечує
   цілісності чи автентичності: зміну шифротексту неможливо виявити. Для реальних даних слід
   використовувати стандартизоване автентифіковане шифрування (наприклад, AES-GCM, FIPS 197,
   NIST SP 800-38D) з перевірених бібліотек.
4. Обмеження реалізації:
   - регістр не зберігається;
   - символи поза задокументованою множиною (латиниця, емодзі) відхиляються;
   - графемні кластери не обробляються;
   - під час виведення на екран додається завершальний перенос рядка, тому точну зворотність форматування гарантує робота з файлами.

# Додаток. Відповіді на контрольні запитання

1. **Що зберігається і що змінюється?** Підстановка змінює символи і зберігає позиції,
   тобто структуру тексту. Перестановка змінює позиції і зберігає набір символів
   та їхні частоти.
2. **Чому одноалфавітна підстановка зберігає частотний розподіл?** Кожна літера завжди
   замінюється тією самою літерою, тому кількість появ переходить без змін, змінюється
   лише «назва» літери.
3. **Коли таблиця оборотна?** Коли це бієкція: довжина 33, лише літери алфавіту, кожна
   рівно один раз.
4. **Додавання і віднімання за модулем у Віженера.** C = (P + K) mod 33. При розшифруванні
   P = (C − K) mod 33, а від'ємний результат зводять до 0..32 додаванням 33.
5. **Чому короткий повторюваний ключ вразливий?** Літери на відстані, кратній l,
   зашифровані тим самим зсувом. Повтори фрагментів (метод Касіскі) або IC дають l, а потім
   кожен стовпець розв'язується частотним аналізом як шифр Цезаря.
6. **Як побудувати обернену перестановку?** Для кожного j покласти `inv[π_j] = j`.
   Для (3, 2, 5, 1, 4) отримуємо (4, 2, 1, 5, 3).
7. **Чому політика неповного блока — частина специфікації?** Від неї залежать шифротекст,
   його довжина і правило розшифрування. Без неї різні реалізації несумісні, а
   розшифрування може втратити або додати символи.
8. **Які символи просувають ключ Віженера?** Лише 33 літери алфавіту після нормалізації.
   Пробіли, цифри й розділові знаки ключ не просувають.
9. **Для чого NFC?** Та сама літера (наприклад, Й чи Ї) може бути закодована одним або
   двома кодовими точками. NFC зводить їх до одного подання, тож пошук в алфавіті та
   порівняння результатів працюють однаково.
10. **Тестовий вектор чи довільний приклад?** Вектор фіксує вхід, ключ і точний очікуваний
    вихід, узгоджені специфікацією. Він виявляє розбіжності між реалізаціями, тоді як
    довільний приклад перевіряє лише узгодженість реалізації самої з собою.
11. **Чому D(E(x)) = x недостатньо для безпеки?** Цю властивість має навіть тотожне
    перетворення. Безпека вимагає, щоб шифротекст не розкривав інформації без ключа, а
    класичні шифри зберігають частоти та структуру.
12. **Що дає автентифіковане шифрування крім конфіденційності?** Цілісність і автентичність:
    будь-яка зміна шифротексту, nonce чи пов'язаних даних виявляється, і розшифрування
    відмовляє.
